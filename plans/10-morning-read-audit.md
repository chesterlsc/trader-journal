# Layout arithmetic and dead space

**The instrument panel is not a new layout — it is a 12-column grid drawn on top of a still-live `@media (min-width: 1240px)` block in styles.css, and the two declarations clay-v3 forgot to restate (`align-items: start` and a 20px `margin-bottom` on every direct child) are the single cause of the metric tiles floating, the panels needing a `height:100%` prop to reach their own track, and the analytics overhanging their row.**

### Two `@media (min-width: 1240px)` blocks at identical specificity — `align-items: start` survives into the instrument panel and turns stretch off for every item
- where: styles.css:9929 (block open), styles.css:9953 (`align-items: start`) vs clay-v3.css:3554 (block open) — clay-v3 never restates it
- does: styles.css:9929 opens `@media (min-width: 1240px)` and sets `#dashboard.is-active { grid-template-columns: minmax(0,1fr) clamp(300px,23vw,360px); row-gap: 0; align-items: start }` at specificity (1,1,0). clay-v3.css:3554 opens a SECOND block at the SAME breakpoint and the SAME specificity, restating grid-template-columns (3564), row-gap (3573) and align-content (3572) — but never align-items. Later file wins ties, so clay-v3 wins the three it names and silently loses the one it does not. `align-items: start` is therefore in force on the 12-column grid: no grid item stretches to its track.
- consequence: This is why clay-v3.css:3602-3609 has to hand `height: 100%` to six named panels one by one, and why the 12-line comment above it at 3595 mis-diagnoses the cause as automatic minimum size (`Stretch alone does not bind`) — stretch does not bind because it was switched off two files ago, not because min-height was auto; `min-height: 0` had already been applied at 3583 and 3591. The two items NOT on the rescue list, `.dash-hero` (3625) and `.dash-quad` (3626), sit at content height inside a hard 96px track: they float in it when content is short and spill past it when content is long. Every future panel added to the grid inherits the same trap.
- fix: Add `align-items: stretch;` beside `align-content: stretch` at clay-v3.css:3572. Then delete the whole `height: 100%` rescue block at clay-v3.css:3602-3609 and the wrong comment above it — six declarations replaced by one, and `.dash-hero` / `.dash-quad` start obeying their tracks for free.
- prize: Retires 6 workaround declarations and a 12-line wrong comment; makes rows 2-4 honest by construction instead of by enumeration. Immediately reclaims the ~26px of slack in row 2 and stops row 3 being overprinted.

### 259.5px of padding on each side is a reading column's gutter applied to an instrument panel, and it is not even centred
- where: styles.css:12167 (`padding-inline: max(var(--space-6), calc((100% - var(--shell-w,100%)) / 2))`), styles.css:3906 (`--shell-w: min(1480px, 96vw)`), clay-v3.css:1035 (`.view.is-active { left: var(--rail-w) }`)
- does: At 1999px: `--shell-w` = min(1480, 1919) = 1480px. The view is `position: fixed`, so the percentage in `padding-inline` resolves against the initial containing block (1999px), not the element — (1999 − 1480) / 2 = 259.5px exactly, matching the measurement. But clay-v3.css:1035 offsets the same box by `left: 56px`, so the element is only 1943px wide while its padding was computed on 1999px. Content = 1943 − 519 = 1424px, sitting from x=315.5 to x=1739.5. The 1480px cap exists to line the page up with `.app-layout { width: var(--shell-w) }` (styles.css:3910) — the top nav pill. That is a document-alignment argument, not an instrument-panel one.
- consequence: 519px of a 1943px box (26.7%) is empty background. The 12 columns are 107.67px each ((1424 − 11×12) / 12); at full width they would be 146.9px. The news rail (cols 10-12) is 345px instead of 465px; the calendar (cols 1-5) is 586px instead of 783px; the equity canvas gets ~700px instead of ~960px, which is why its y-axis labels overprint into mush. Separately, the 56px rail offset is never subtracted from the padding, so the whole content column sits 28px right of the viewport centre — 42px when `body.rail-pinned` makes `--rail-w` 84px (clay-v3.css:731). No, 1480px is not defensible here: a monitor 519px wider than the cap renders byte-identical to a 1480px one. A reading column caps measure because long lines hurt reading; an instrument panel has no measure to protect — its columns are gauges and every extra pixel is resolution.
- fix: In the clay-v3 1240 block, opt the dashboard out of the shell column with one line: `#dashboard.is-active { padding-inline: var(--space-6); }` at (1,1,0) — it beats `.view.is-active:not(#terminal)` at (0,2,0). The desk (`#terminal`) already does exactly this and the comment at styles.css:12163 already blesses the precedent: "The Edge desk stays full-bleed: it is an instrument, not a document." The dashboard is the same kind of thing.
- prize: 471px of usable width (519 reclaimed, 48 kept as gutters). Column pitch 107.7px → 146.9px, +36%. News rail +120px, calendar +197px, equity canvas +260px. Also kills the 28px off-centre error, since the padding stops being derived from a viewport the element does not span.

### `align-content: start` on the rail means its own scroller can never engage — 146px of news is clipped, not scrolled
- where: styles.css:9607 (`.dash-edge-mini { align-content: start }`) fighting clay-v3.css:3672-3676 (`#dashboard.is-active .dem-panel { min-height: 0; overflow-y: auto }`)
- does: `.dash-edge-mini` is `display: grid` (styles.css:9605) with `align-content: start` (9607). clay-v3.css:3607 gives it `height: 100%` and `overflow: hidden`, so its box is exactly row 4 = 477.9px. But `align-content: start` sizes every row to content and packs them at the top — the `.dem-panel` row is auto-sized to its full content height and simply runs off the bottom. `overflow-y: auto` on `.dem-panel` (3674) is a no-op because the element is never shorter than its content. Arithmetic: row 4 spans y=656 to y=1134. `.dem-cmd` ≈ 48px; `.dem-tv` is 11px padding + a 16:9 picture at (345 − 2 − 22) = 321px wide → 180.6px tall, so 191.6px. 48 + 191.6 = 239.6, putting `.dem-news` at y≈896 (measured 899). `.dem-news` wants 381px → bottom 1280, i.e. 146px past the 1134px box. `.dem-screen` and the F1 key below it are 100% gone.
- consequence: It is worse than 'below the fold' — `overflow: hidden` on the rail means there is no scrollbar and no gesture that reaches it. The news feed, the terminal screen and the 'open the desk' key are permanently unreachable at this viewport. The rail reports 478px and paints 624px. Note also that `#dashboard.is-active .dash-edge-mini > *` (clay-v3.css:3591) only floors `.dem-cmd` and `.dem-panel`; `.dem-news` is a grandchild and is never floored.
- fix: The smallest honest fix is one line in the clay-v3 1240 block: `#dashboard.is-active .dash-edge-mini { grid-template-rows: auto minmax(0, 1fr); }`. That bounds the `.dem-panel` track, at which point the `overflow-y: auto` already written at 3674 starts working and the news becomes scrollable instead of amputated. (`align-content: stretch` would do it too but would also stretch `.dem-cmd`.) Second, cheaper win: the 16:9 tile eats 192px — capping it with `max-height: 150px` gives the news 42px back before any scrolling is needed.
- prize: 146px of clipped content becomes reachable; three UI elements (news feed tail, terminal screen, F1 key) go from unreachable to available. Zero layout height added.

- where: styles.css:9962 (`#dashboard.is-active > *:not(:last-child) { margin-bottom: var(--space-5) }`) — reset for exactly one element at clay-v3.css:3655

### The 96px row is reverse-engineered from a decorative min-height, and that same declaration is what makes the tiles clip
- where: styles.css:7501 (`.metric-card:not(.dash-rail-item) { min-height: 96px }`) + styles.css:2691 (`align-content: center`) → track at clay-v3.css:3565 (`grid-template-rows: 44px 96px ...`)
- does: `.dash-quad-card { min-height: 108px }` at styles.css:4817 is (0,1,0) and LOSES to `.metric-card:not(.dash-rail-item) { min-height: 96px }` at styles.css:7501, which is (0,2,0). - fix: In the clay-v3 1240 block: `#dashboard.is-active .dash-quad-card { min-height: 0; }` and change the row 2 track from `96px` to `auto` (clay-v3.css:3565). One source of truth: the tile sizes to its content, the row sizes to the tile.
- prize: ~26px returned from row 2 to rows 3/4 at rest, and the clip stops entirely. Combined with the `align-items: stretch` fix above, row 2 becomes self-sizing and never lies again.

### One line in charts.js is the root cause of every chart complaint on the list.
- where: src/modules/charts.js:1625
- does: `const height = Number(heightOverride || canvas.dataset.height || 280);` — getCanvasContext sizes the bitmap from the authored data-height attribute and never reads the box it is actually painted into, while clay-v3.css:3613 sets `#dashboard.is-active .panel-chart canvas { height: 100% }`. - fix: `const height = Number(heightOverride) || canvas.clientHeight || Number(canvas.dataset.height) || 280;` — heightOverride still wins so drawBarChart's fitHeight at charts.js:1073 is unaffected, and a hidden canvas reports clientHeight 0 and falls through to data-height exactly as today. - prize: Every chart in the product draws at the size it is displayed at. Two lines, seven charts, and the mush is gone.
